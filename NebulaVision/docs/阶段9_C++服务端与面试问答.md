# 阶段9 最小C++接口服务

## 结果
新增backend/server.pro、main.cpp、apiserver.h/.cpp，Qt6 HTTP Server实现健康检查、通道和事件接口，监听127.0.0.1:18880。
技术选择：原计划Drogon为候选，本机Qt6已带HTTP Server，沿用Qt事件循环和工具链。没有声称已使用Drogon。

## 调用链与代码
主函数读server.local.json → ApiServer注册路由 → QTcpServer监听本机 → HTTP请求转ApiRequest快照 → QtConcurrent工作线程 → ServerDb创建独立连接 → 参数化SQL → JSON响应。
请求快照复制路径、方法、参数、请求体和Authorization，不把原始HTTP对象跨线程引用。
ServerDb按请求创建命名连接，先销毁SQL查询，再关闭和移除连接。服务只允许nebulavision_dev。
GET /health不依赖数据库；GET /api/cameras列通道；GET /api/events支持page、size、UTC date。
数据库故障返回503，查询参数错误400，方法错误405。当前阶段接口未加业务登录，阶段11接入。

## SQL和参数
统计与列表使用同一日期条件，时间半开区间，按时间及id稳定排序，页码越界收敛到末页。参数只允许合法日期、page 1至1000000、size 1至100。
当前没有连接池，每个请求打开连接，适合本机开发验证；不是高并发性能承诺。线程池和请求数仍需后续容量控制。

Release编译通过。实际HTTP health=ok，事件总数1，通道1。测试记录x/验证记录/阶段9到16/stage9.json。
未改原smart_monitor，未将服务暴露到局域网或互联网。

## 面试追问和答案
1. HTTP服务和数据库服务一样吗？不是，HTTP处理业务契约，MySQL管理持久数据。
追问 为什么用JSON？跨语言方便，字段和错误码仍需明确约定。
2. 为什么数据库放工作线程？同步驱动会阻塞，避免占住HTTP事件循环。
追问 线程池自动解决并发容量吗？不是，还要连接池、限流、超时和负载测试。
3. 为什么每个线程新建连接？Qt SQL连接有线程归属，句柄复制不建立新连接。
4. 400、401、403、503区别？参数错、未认证、无权限、依赖不可用。阶段11接入认证状态。
5. 为什么只监听本机？当前是开发服务，远程部署另需TLS和服务配置。
