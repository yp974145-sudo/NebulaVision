## 调用链与原理
main诊断分支 -> DevDbConnection::open -> JSON配置校验 -> 创建独立命名QMYSQL连接 -> SELECT DATABASE(), CURRENT_USER() -> 校验真实连接身份 -> 析构关闭。
旧DbConn使用默认连接；新模块使用UUID命名连接，避免覆盖默认连接。
配置错误在连接前拒绝；连接后的查询用于再次验证服务端实际库和账号。
QSqlDatabase副本共享同一连接，不是自动建立另一条连接。使用者必须在连接对象销毁前释放查询和数据库句柄，并在创建线程使用连接。
当前为同步开发诊断，未来UI查询阶段再做异步处理。

## 如何运行
在配置好Qt运行库的终端执行：bin/class15.exe --check-dev-db
本地配置不纳入Git；移动电脑后需要重新配置账号密码。

## 面试追问
1. 为什么命名连接？防止新业务覆盖原默认连接，隔离生命周期。
2. 为什么不只校验库名？还需专用账号及数据库端最小权限，代码检查不能代替授权。
3. 为什么先销毁QSqlQuery再removeDatabase？查询/句柄仍引用连接时移除会造成失效引用。
4. 为什么不把密码写进日志？错误提示只给出操作方向，不输出凭据。
