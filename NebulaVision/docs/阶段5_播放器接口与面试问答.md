## 接口怎样理解
```cpp
virtual void open(const QString &source) = 0;
virtual void pause() = 0;
virtual void resume() = 0;
virtual void stop() = 0;
```
virtual表示允许子类提供具体行为，=0表示接口本身没有实现，子类必须实现。
窗口持有VideoPlayer指针，实际创建QtVideoPlayer。调用player->pause时运行子类实现。
这样阶段6换FFmpeg实现时，按钮仍调用同样的open/pause/resume/stop。
这叫接口与实现分离，不等于已经实现插件热加载。

## Qt实现逐步说明
构造时new QMediaPlayer(this)创建播放器，new QVideoWidget(parent)创建显示控件，setVideoOutput将两者连接。
open先停止上次播放，QFileInfo检查路径，QUrl::fromLocalFile构造本地文件地址，再setMedia和play。
pause/resume/stop分别调用Qt播放器的pause/play/stop。
stateChanged信号转换成中文状态，error信号给出可读错误，由监控页标签显示。
QObject父子关系负责销毁播放器；显示控件由窗口父子关系管理。后续子类也必须管理自己的线程与进程资源。

## 监控页改动
原单画面QLabel改成player->videoWidget()。打开按钮用文件选择框得到路径，再调用player->open。

## 真实测试结果
Qt5.9.8/MinGW5.3 32位主项目和stage5_check编译通过。
FFmpeg生成的无压缩AVI由Qt媒体后端实际解码，QVideoProbe收到多帧；暂停、继续、停止、再次打开和不存在文件均通过，测试退出码0。
测试MP4在本机DirectShow后端报0x80040266，未通过。不能声称Qt后端已支持所有MP4；阶段6改用FFmpeg验证同一MP4。
探针测试结束时Qt插件有引用清理警告，后续测试已安排显式解除探针来源；它不代表已完成所有Windows媒体后端兼容验证。

## 面试问答
1. 为什么加VideoPlayer接口？让界面依赖统一操作，底层Qt或FFmpeg实现可以替换。
追问 虚函数怎么分派？通过基类指针调用虚函数，会执行实际对象类型的重写实现。
2. QMediaPlayer和QVideoWidget分别干什么？前者控制媒体播放，后者显示视频输出。
3. 文件后缀是MP4就一定能播吗？不是。容器、内部编码及本机后端能力都会影响。本机AVI通过、测试MP4失败，已经如实记录。
4. QObject父子关系能管理线程结束吗？能销毁子对象但不能代替线程安全退出，FFmpeg阶段要先停工作再销毁。
5. 打开失败怎么办？文件不存在先拒绝；后端错误通过信号给页面提示，避免静默失败。
6. 接口为什么继承QObject？方便统一提供状态和错误信号；不意味着QObject天然线程安全。
