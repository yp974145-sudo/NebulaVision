## 授权链路
登录令牌 → API检查camera_id权限 → 签发包含会话哈希、摄像头、流路径、read/publish动作、过期时间的媒体令牌 → 客户端RTSP连接 → MediaMTX HTTP回调 → C++校验签名、范围、当前会话及资源权限 → 允许或拒绝。
普通用户可申请已授权摄像头read，只有管理员可publish。未配置enabled的摄像头拒绝播放。
媒体令牌最多1小时且不超过登录会话到期，回调返回expireAt让媒体服务关闭到期连接。当前没有自动刷新媒体令牌；过期后需重新登录或重新打开设备。
退出登录会阻止后续媒体鉴权，但已建立的连接不是即时撤销，需要额外踢流机制；当前依靠到期关闭，不能声称即时踢流已实现。

## 入门逐段讲解
### 为什么业务登录还不够
API登录保护的是接口。媒体播放器直接连接RTSP，如果媒体服务不鉴权，别人即使不调用API也可能看流，所以要让MediaMTX回调业务服务检查凭据。
### 签名包含哪些东西
本例签名覆盖会话、摄像头编号、媒体路径、read或publish动作和过期时间。修改任意一项都会使签名不匹配。
```text
JSON声明 → Base64URL编码 → 用共享密钥计算HMAC
媒体令牌 = 编码后的声明 + 点号 + 签名
```
编码不是加密，能解开看到声明，不应把密码放进去。该两段令牌是本项目自定义的范围凭据，不把它冒充标准JWT。
### 播放地址从哪里来
用户双击服务端设备，后台POST media/play，服务端检查权限后返回带短期凭据的地址，再交给原来的VideoPlayer。窗口不读取摄像头表中的秘密连接信息。
### 三层检查
API签发时查权限，媒体回调时验签及会话，回调还检查动作和路径范围。因此A摄像头的read令牌不能用来publish或访问B摄像头。
追问：有签名为什么还查会话？答案：签名证明凭据由服务签发，不自动证明对应登录会话此刻仍有效。已经建立的媒体连接还要单独设计主动撤销。

## 面试追问与答案
1. 控制平面和媒体平面是什么？API决定谁可看哪路流，媒体服务负责传输流量，二者通过受限凭据连接。
2. 为什么地址不等于权限？裸地址被转发后任何人可能尝试访问，必须由媒体服务验令牌。
3. HMAC是什么？用双方共享密钥对消息认证，能检验篡改；签名载荷并不加密，不放密码。
4. 为什么令牌绑定路径和动作？防止拿读令牌发布，或拿A摄像头令牌访问B摄像头。
5. 回调能直接信任传来的ip/user吗？不能，仅根据经过验签的声明、有效会话和数据库权限授权。
6. 过期与撤销相同吗？不同，现有流到期关闭不等于logout立即踢流，需要另实现主动撤销。
