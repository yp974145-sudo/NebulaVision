# 阶段18 中文文档检索与面试问答

## 目标和结果
原主窗口查询助手增加“文档 问题”入口，例如文档 登录失败怎么办。使用真实中文嵌入模型BAAI/bge-small-zh-v1.5，将六份指定的技术文档切成62块，保存在本机Qdrant Local持久化索引。回答展示最多三段相关原文、文件名、标题和文档SHA256。

这是RAG中的检索和证据组织部分，未接大语言模型生成。没有把原文摘录称为完整生成式问答。Qdrant运行于进程内本地模式，没有部署独立Qdrant服务集群。

## 文件与调用链
agent/retrieval.py负责分块、嵌入、索引和检索。index_documents.py是文档变更后可重复使用的维护入口，属于正式工具，不是一次性脚本。retrieval-requirements.txt固定本次库版本。agent/client.py识别文档前缀，先调用已有/api/me验证登录，再执行检索。view/mainwidget.cpp展示该入口提示。tests/retrieval_check.py验证来源、权限和过期引用。

调用链：Qt输入文档问题 → Python校验登录 → 查询向量 → Qdrant余弦检索和public过滤 → 文件白名单及哈希复核 → 原文摘录与引用 → Qt显示。

## 代码逐段讲解
DOCUMENTS是明确指定的文件名单。索引只读这六份文档，不遍历整个电脑、不读取本机账号JSON、不索引数据库配置。当前六份都是可分享技术文档，权限标签均为public。未来加入私有文档必须增加真实角色或账号授权，不能只改提示语。

chunks依次读取文件。遇到新标题或当前段落加下一行超过600个字符，就输出一块。单行本身很长时仍可能超出600，所以这里是软上限，不是严格token上限。只有标题、没有正文的块会被跳过。yield表示每次交出一个块，调用方通过list收集全部结果。

每块保存source文件名、heading标题、text原文、sha256文件摘要和visibility标签。SHA256用于检查内容版本，不能证明文档内容一定正确，也不提供加密。

TextEmbedding把中文文本转换为数值向量。这里是实际下载运行ONNX嵌入模型，不是用关键词计数假装语义向量。model.embed返回多条向量；向量长度用于创建Qdrant集合，距离使用COSINE。

QdrantClient(path=...)使用本机磁盘模式。PointStruct的id是块编号，vector存向量，payload存来源和权限等文字信息。upsert写入点。维护入口会重建集合，重建期间不要同时启动查询；没有实现生产环境无中断索引切换。

search先将问题变成向量，再通过query_points检索相近块。limit=3限制返回数量；score_threshold=0.5是本次初始阈值，不是已校准的准确率。Filter在向量数据库内限制public，不是取出私有原文后再隐藏。

检索后再次检查文件名是否在名单中、磁盘文件SHA256是否等于索引版本。不一致就不引用旧块。没有剩余证据时明确显示未找到，不编写无依据答案。文档中的文字只用于展示，不会成为shell、SQL或工具调用指令。

Qt的进程超时仍为20秒，首次模型下载应通过维护入口预先完成。模型、rag-python依赖及document-index保存在外部资源目录，属于运行资源，不能当作本次临时校对文件删除。

## 验证和边界
真实模型及索引检查通过三组来源：登录返回问题→登录与返回修复说明；Redis故障→阶段14；录像缺失→阶段13。测试另向临时索引副本写入admin标签的高相似度点，public查询不返回它；修改临时文档副本后，旧索引引用被拒绝。测试只修改任务临时目录副本，不破坏正式索引。

三组问题不是完整检索评估集。未评估召回率、噪声问题误命中率、长文截断、并发访问和多角色私有知识库。当前固定阈值仍可能返回不相关片段；没有LLM校验和生成。事件数量必须调用业务API，而不是从文档里猜测。文档随代码变化时，需要运行索引维护入口更新。

## 面试问题与追问答案
问题1：向量是什么？答：模型把文本编码成一组数，相近含义通常有较近的向量。追问：相似度高就代表答案正确吗？答：不代表，仍要看原文、版本、适用范围及权限。

问题2：为什么要分块？答：避免整篇文档的不同主题混在同一向量中，也方便引用具体段落。追问：600字符一定小于模型长度吗？答：不一定，字符和token不同，本阶段没有严格token分块评估。

问题3：Qdrant存什么？答：向量、点ID与payload。payload里保存来源、标题、原文和权限标签。追问：查询权限放哪里？答：在数据库Filter里先限制public，检索后再检查文件白名单和版本。

问题4：为什么引用需要SHA256？答：检索索引可能落后于文档，哈希不一致说明版本变化。追问：哈希一致能证明结论可靠吗？答：不能，只证明本次引用对应磁盘这一版内容。

问题5：RAG和实时业务查询有什么区别？答：文档检索解释技术知识，结构化API查询给出当前账号可见事件和计数。追问：能把文档中的历史事件数当今天总数吗？答：不能，应调用实时业务接口核对。

问题6：这是不是完整RAG？答：目前完成语义检索与证据展示，没有生成模型。追问：下一步接生成模型要补什么？答：模型配置、超时、来源约束、输出校验及引用准确性评估，并明确哪些资料会离开本机。

## 练习和资料
输入“文档 登录后返回按钮没有反应怎么办”，核对引用文件。再打开对应Markdown，对照摘录是否来自原文。不要把问题中的指令当作修改数据库的授权。

Qdrant官方本机说明：https://qdrant.tech/documentation/quickstart/ 。FastEmbed实现来源：https://github.com/qdrant/fastembed 。模型标识为BAAI/bge-small-zh-v1.5，下载缓存保留在本机embedding-models。
