# 完整启动入口修复

用户双击启动失败时，后台六个进程实际都存活。复现同一个CMD入口，得到nul和xe不是命令的错误，退出码1。检查文件字节发现只有1个CR却有3个LF，启动脚本存在混合换行。

修复后CMD全部使用ASCII正文及CRLF，转交ASCII文件名start-demo.ps1。PowerShell脚本使用带BOM的UTF-8，兼容Windows PowerShell对非ASCII路径的解析。用户可双击x下启动完整演示.cmd或停止完整演示.cmd，原来带阶段9到16的名称仍可使用。

scripts/install_launchers.py是保留在仓库的正式安装工具，用于重新生成这些入口。scripts/demo_launcher.py复用项目已有管理器，检查已记录进程的PID、创建时间与路径，确认ready和API健康后再打开客户端。失败返回非零，CMD保留窗口显示错误，不再默默关闭。成功会清理历史last-error，避免旧错误误导排查。

停止和冷启动两个正式CMD入口均实际执行成功，输出Services stopped与Services ready. Client opened，退出码0。启动仍是本机开发工具，不代表生产环境系统服务或Docker编排已经部署。

同类多服务项目常将Qt客户端、业务API、媒体、缓存、检测各自作为进程，再由脚本、服务管理器或Compose组织。具体项目应查它自己的启动说明，不能认定所有项目都一样。
