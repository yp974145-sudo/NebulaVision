## 代码与原理
users.password_hash保存pbkdf2_sha256、200000轮、16字节随机salt和32字节派生值。每个用户不同盐，不是旧项目MD5。
QPasswordDigestor派生后按字节累计差异比较；未知用户也执行派生，避免明显的存在性时间差。用户名和密码长度有限制。
成功后系统随机数生成32字节令牌，只把令牌哈希作为会话表键，内存保存用户id和到期时间。重启服务需重新登录，当前没有持久会话或刷新令牌。
每次请求检查账号active和当前角色；管理员全部资源，普通用户只查权限表授权的摄像头。事件查询也按camera_id限制，不是只隐藏按钮。
登录有本机计数限流，阶段14接入Redis；当前计数是按用户名，不是完整分布式风控。
客户端QFutureWatcher与QtConcurrent做后台登录，回GUI后写ApiSession并显示用户名，密码不存盘。

## 入门逐段讲解
### 注册账号与登录校验的两次计算
初始化账号时随机生成salt，用密码、salt和200000轮PBKDF2得到派生值。数据库保存算法、轮数、盐和结果；登录时用输入密码重复计算后比较。
数据库里不是可以解密回明文的密码。不同盐让相同密码也得到不同结果；盐不是另一个用户需要记住的密码。
### 令牌怎样发放和使用
登录成功后生成随机字符串，响应交给客户端。后续请求头写`Authorization: Bearer <令牌>`。服务端把收到的令牌哈希后查会话表，找到用户id与到期时间。
```cpp
QMutexLocker lock(&sessionMutex);
auto session = sessions.value(key);
if (session.second < QDateTime::currentDateTimeUtc()) {
    sessions.remove(key);
    return fail("expired session", 401);
}
```
锁保证多个工作线程不会同时破坏会话容器。session.first是用户id，second是到期时间。返回401结束本次请求，后续SQL不会继续执行。
### 用户为什么仍可能拿到403
会话有效只说明身份成立，还要查角色或user_camera_permissions。管理员可访问全部摄像头，viewer只访问明确授权的摄像头。授权检查在服务端，即使用命令绕过窗口也不能省略。
### 登录窗口为什么用watcher
后台任务返回数据，QFutureWatcher在完成后通知窗口。窗口在GUI线程恢复按钮和显示错误，不让网络等待卡住登录界面。密码框立即清空，不写进本地日志。
追问：退出只清空界面用户名够吗？答案：不够，要使服务端会话失效，并清客户端令牌；当前退出还会停止本机预览。

## 面试追问与答案
1. 认证和授权区别？认证确认你是谁，授权确认你能操作哪个摄像头。登录成功不等于可访问全部资源。
2. 为什么不能直接MD5密码？快速哈希不适合口令存储；本例用带盐的PBKDF2，验证要重复同样派生。
追问 盐要保密吗？不需要，它与哈希一起保存，用来避免相同口令得到相同结果；不等于密码。
3. 为什么会话只存令牌哈希？减少会话表泄漏时直接拿令牌重放的风险；客户端仍必须保护原令牌。
4. 退出后怎样失效？服务端移除会话，后续请求无法命中；客户端清空内存不等于服务端退出，必须调用logout。
5. 403和401区别？没登录或令牌失效是401，身份有效但资源无权限是403。
6. 为什么服务重启要登录？会话当前在进程内存，尚未迁到共享存储。
7. 客户端能不能只隐藏无权限按钮？不能，攻击者可直接发HTTP请求，服务端必须重复校验。
