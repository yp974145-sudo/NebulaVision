## 四、eventrepository.h：先规定“数据放在哪里”
### 4.1 EventData是一条事件
```cpp
struct EventData {
    QString id;
    QString cameraName;
    QString occurredAt;
    QString type;
    QString description;
    QString status;
};
```
struct把几个相关变量放在一起。它不是数据库表，而是程序内存中的一个数据类型。
```cpp
EventData event;
event.id = "1";
event.cameraName = "学校东门";
```
第一句创建变量，后面通过点号访问它的成员。上面是说明用例，实际内容从数据库读取。
这类只用来传数据的对象通常称为DTO。先理解“装一条事件的盒子”，再记英文缩写。

### 4.2 EventResult装一次查询的结果
```cpp
struct EventResult {
    QVector<EventData> events;
    QString error;
};
```
QVector<EventData>是能存放多条事件的列表。append添加一条；size获取条数；at取指定位置；isEmpty判断是否为空。
error保存错误原因。三种情况要分清：
|error|events|含义|
|---|---|---|
|空|有数据|查询成功，有记录|
|空|空|查询成功，没有记录|
|非空|本实现返回空列表|查询失败|
空列表本身不能证明失败。

### 4.3 查询函数的声明
```cpp
EventResult queryLatest(const QString &configPath);
```
接收配置文件路径，返回EventResult。const表示不修改参数，&表示引用传递。这里参数里的&不是调用时取地址的写法，不要混淆。
.h声明有这个函数，.cpp写具体执行步骤。

## 五、eventrepository.cpp：怎样从数据库取事件
### 5.1 准备结果并连接
```cpp
EventResult result;
DevDbConnection connection;
QString error;
if (connection.open(configPath, &error) == false) {
    result.error = "新库连接失败：" + error;
    return result;
}
```
先准备空结果，创建连接管理对象，再调用阶段1的open。&error取字符串地址，使open能够把错误说明写回来。
本函数返回类型是EventResult，所以这里返回result；open返回类型是bool，所以它返回true/false。
return会立即结束当前函数，不会继续执行后面的查询。

### 5.2 创建查询对象
```cpp
QSqlQuery query(connection.database());
```
query使用这条新库连接。没有省略连接参数去使用原来的默认连接。
connection.database()返回连接句柄副本，并不是再建立一条物理连接。

### 5.3 SQL逐句理解
```sql
SELECT e.id, c.name, e.occurred_at, e.event_type,
       e.description, e.status
FROM events e
LEFT JOIN cameras c ON c.id=e.camera_id
ORDER BY e.occurred_at DESC, e.id DESC
LIMIT 100;
```
- SELECT后面规定要取哪些列，以及列的顺序。
- events e是给事件表起简称e；cameras c同理。
- e.camera_id保存摄像头编号，通过它找到c.id，从而取出c.name。
- LEFT JOIN即使没有匹配摄像头，也保留左侧事件；当前外键正常情况下也会约束关联有效。
- DESC表示从大到小，时间就是从新到旧。
- 同一时间再比较唯一的id，使相同时间的记录也有确定顺序。
- LIMIT 100最多返回100条，不是数据库总条数。
代码里多行相邻字符串会自动拼接成一条SQL，不是执行多条SQL。
该SQL目前没有用户输入；将来添加日期筛选时使用prepare/bindValue，避免拼接用户输入。

### 5.4 执行和逐行读取
```cpp
if (query.exec(sql) == false) {
    result.error = "事件查询失败，请检查新库表结构和账号查询权限。";
    return result;
}
while (query.next()) {
    EventData event;
    event.id = query.value(0).toString();
    // 其余字段同理
    result.events.append(event);
}
```
exec负责执行SQL；next负责移动到下一行，两者不同。刚执行完时还没定位到第一条记录，必须先next才能读取。
value列号从0开始：0编号、1名称、2时间、3类型、4描述、5状态。
toString将值转换成字符串。时间先toDateTime，再按yyyy-MM-dd HH:mm:ss.zzz格式生成文字，zzz表示毫秒。
UTC是当前项目的存储约定，DATETIME字段本身不保存时区；仅在表头写UTC不会自动转换时区。

### 5.5 读取失败与返回
循环后检查lastError；如果读取过程中出现错误，清空不完整数据并填写error，避免把半份结果当成功。
正常时return result，把事件列表传给调用者。
局部对象按创建的逆序销毁：query先销毁，connection后销毁，避免移除连接时查询仍引用它。这是本阶段的资源生命周期重点。

## 六、eventservice.h：为什么中间还有一层
当前它负责确定配置路径，再调用查询类。代码比较短，是给后续业务规则留边界，不代表已经有复杂业务。
```cpp
EventResult queryLatest(const QString &configPath = QString())
```
= QString()提供空字符串默认值，因此可以不传路径。
如果path.isEmpty()，使用exe所在目录，加上../NebulaVision/config/viewer.local.json。
../是返回上一级，不是整个电脑搜索配置。
```text
项目目录
├─ bin/class15.exe
└─ NebulaVision/config/viewer.local.json
```
这也意味着移动exe、没有同时带上配置时会失败；当前路径是本地开发约定，最终部署需要单独设计。
最后return repository.queryLatest(path)，把结果原样交回窗口。
函数直接定义在类里面，所以本阶段没有另外的eventservice.cpp。

### 8.4 loadPage分流
```cpp
if (typeBox->currentIndex() == 1) {
    loadEvents();
    return;
}
```
选择新事件就执行新函数并结束loadPage，否则继续原录像代码。旧RecordModel、RecordService本次没有改写。

### 8.5 loadEvents先清表、设表头
clear清除单元格和表头内容；setRowCount(0)清除旧行；setColumnCount(6)准备六列，然后重新设置表头。
先清空是为了避免连接失败后还显示旧结果，让用户误以为刚查询成功。
QStringList是字符串列表，headers << "编号"是向列表添加文字。

### 8.6 禁用分页和阻止重复查询
previous和next禁用。jump临时blockSignals(true)，再把范围和值设为1并禁用，最后恢复信号。
原因：程序调用setValue也可能触发valueChanged，原连接会再次执行loadPage。临时阻断避免设置页码时重复查询。

### 8.7 请求数据并判断错误
```cpp
EventResult result = eventService.queryLatest(eventConfigPath);
```
这句将页面与查询链路接起来。有error时显示失败并return，没有error才填表。
这句目前同步执行，会等待数据库返回；不能因为是信号槽触发就说已经异步。

### 8.8 逐行显示
```cpp
for (int row = 0; row < result.events.size(); row++) {
    EventData event = result.events.at(row);
    table->insertRow(row);
    table->setItem(row, 0, new QTableWidgetItem(event.id));
}
```
row是界面行号；at(row)取列表里同位置的事件；insertRow新增行；setItem指定行、列和单元格。
六列对应EventData六个成员。new创建单元格对象，setItem交给表格后由表格管理，不再手动delete。
内存里的事件列表和屏幕上的表格是两个不同对象；for循环把数据转换成界面内容。

### 8.9 列宽、数量与空提示
ResizeToContents让列宽适应内容；setStretchLastSection让最后一列使用剩余空间。
QString中的%1是占位符，arg(result.events.size())替换成实际显示条数。
结果列表为空且error为空时显示暂无事件，不显示连接失败。

### 8.10 双击不能把状态当录像路径
旧逻辑把最后一列当成本机视频路径；新事件最后一列是状态。
因此新事件模式双击只提示暂未接入录像播放并return，避免把test等状态文字当成文件名。

## 十一、面试问题、继续追问与参考答案
下面的答案只描述本项目已经做的事，未完成的功能明确说后续规划。

### 1. 这一阶段做了什么？
答：在原Qt回看页接入新库事件查询，默认展示最近100条，补了错误和空数据提示，并将SQL放在独立查询类中。
追问：是不是完整回看功能？
答：不是。当前只显示事件，事件录像播放尚未接入，新事件日期分页下一阶段做。

### 2. 为什么窗口不直接写SQL？
答：窗口负责显示和交互，查询类负责SQL和结果转换。数据库字段变化可以集中修改查询代码，界面不用同时了解表结构。
追问：Service现在为什么这么薄？
答：本阶段业务简单，只确定配置并转交请求；后续再放日期页码校验，不为分层强行增加逻辑。

### 3. DTO是什么？
答：用于传数据的对象。本项目EventData保存一条事件，EventResult保存列表和错误，不直接操作数据库或控件。
追问：它和数据库表相同吗？
答：不同。EventData包含关联查询得到的cameraName，是为了展示整理的数据，不是events表的原样复制。

### 4. exec和next有什么区别？
答：exec执行SQL；next移动到结果的下一行。查询成功也可能没有数据，需要next成功后才能读取当前行。
追问：value(0)的0是什么意思？
答：SELECT结果中的第一列，下标从0开始，不是事件id为0。

### 5. 为什么使用LEFT JOIN？
答：通过camera_id取摄像头名称，同时保留左侧事件记录。没有匹配时摄像头名称为空；当前外键正常情况下也约束关联有效。
追问：和INNER JOIN有什么区别？
答：INNER JOIN仅返回两侧匹配的行，LEFT JOIN保留所有左侧行。不能笼统说LEFT JOIN一定更快。

### 6. 为什么按时间和id一起排序？
答：不同事件可能同一时间发生，追加唯一id作为次序依据，使结果排序确定。
追问：这就完全解决动态数据分页问题了吗？
答：没有。阶段2还未实现新事件分页。未来OFFSET分页在数据新增时仍可能重复或遗漏，需要根据需求考虑快照或游标分页。

### 7. LIMIT 100代表总共100条吗？
答：不是，只代表最多返回100条；页面显示的是已加载数量。全库总量需要另做COUNT统计。
追问：已有索引一定能完美支持这个查询吗？
答：不能保证。已有(camera_id,occurred_at,id)主要面向按摄像头查时间；当前全摄像头时间排序应结合EXPLAIN和数据量评估是否新增时间索引。

### 8. 为什么不把所有行一次读完？
答：限制结果量能控制传输、内存和填表开销。本阶段先用100条上限，后面做真正分页。
追问：QTableWidget适合无限数据吗？
答：不适合。当前小列表足够；大规模数据可考虑QTableView配合数据模型及分页，但当前未迁移。

### 9. 怎样区分无数据和失败？
答：error为空且列表为空表示成功无数据，error非空表示失败。失败先清表，避免残留旧结果。
追问：查询一半断线怎么办？
答：本实现读取结束后检查lastError，出错清掉不完整结果并返回错误；尚未做真实中途断线注入验证。

### 10. 为什么query要比连接管理对象先销毁？
答：query仍引用连接时移除连接会产生失效引用和警告。这里先创建connection再创建query，函数退出时局部对象逆序销毁。
追问：返回QSqlDatabase副本是不是新连接？
答：不是，副本共享底层连接，所以调用者不能让它超过连接管理对象的寿命。

### 11. 表格中的new要自己delete吗？
答：setItem后单元格所有权交给表格，清除或销毁表格时释放；不能再随意手动释放同一单元格。
追问：这是否等于所有new都不需要管？
答：不是，取决于对象所有权规则。本例是QTableWidget接管item。

### 12. 信号槽是不是自动异步？
答：不是。当前界面触发loadEvents，数据库查询仍同步执行在GUI线程。
追问：数据库很慢会怎样？
答：界面可能卡住。阶段4才移到工作线程，线程中建立自己的连接，通过队列信号把结果交回GUI。

### 13. 为什么blockSignals？
答：代码更新跳页框的值也可能触发valueChanged，导致重复查询；设置时临时屏蔽，完成后恢复。
追问：会不会把别的对象的信号都停掉？
答：不会，这里只屏蔽jump对象发出的信号，不会冻结整个应用。

### 14. Lambda的捕获和参数有什么区别？
答：[this, query]让函数体使用外部对象和按钮指针；(int index)是信号触发时传来的选项编号。
追问：捕获指针会延长对象寿命吗？
答：不会。本连接提供this作为接收上下文，对象销毁时Qt会断开对应连接；仍需避免让其他捕获对象提前销毁。

### 15. 为什么JSON配置不放Git？
答：本地viewer.local.json包含真实密码，被忽略；源码与配置分开。换电脑需要单独配置，不能只复制源码就假定能连接。
追问：.gitignore能删除已经提交过的密码吗？
答：不能。它只影响未跟踪文件；已进入历史的凭据需要另处理并更换。本项目这份本地配置未纳入提交。

### 16. UTC表头会自动转换时间吗？
答：不会。当前把数据库值按UTC存储约定格式化显示；DATETIME没有时区信息。后续要在写入、查询和显示各处统一时间约定。

### 17. 专用账号怎样保护旧库？
答：阶段1已经检查专用账号仅有nebulavision_dev的SELECT授权；本阶段事件查询复用它。代码校验和数据库端授权共同限制访问。
追问：整个客户端都不访问旧库了吗？
答：不是。新事件分支走新库，原录像和登录注册代码尚未全部迁移，不能把局部改造说成全系统迁移。

### 18. 如何证明不是只写代码没运行？

```cpp
#include "eventrepository.h"
#include "../util/devdbconnection.h"
#include <QSqlQuery>
#include <QSqlError>
#include <QVariant>
#include <QDateTime>

EventResult EventRepository::queryLatest(const QString &configPath)
{
    EventResult result;
    // 先创建连接管理对象，后创建query；返回时query会先销毁。
    DevDbConnection connection;
    QString error;
    if (connection.open(configPath, &error) == false) {
        result.error = "新库连接失败：" + error;
        return result;
    }

    QSqlQuery query(connection.database());
    // JOIN通过camera_id找到摄像头名称；LEFT JOIN保留未匹配到摄像头的事件。
    // 阶段2仅展示最近100条，日期筛选和分页留到阶段3。
    QString sql = "SELECT e.id, c.name, e.occurred_at, e.event_type, "
                  "e.description, e.status "
                  "FROM events e LEFT JOIN cameras c ON c.id=e.camera_id "
                  "ORDER BY e.occurred_at DESC, e.id DESC LIMIT 100";
    if (query.exec(sql) == false) {
        result.error = "事件查询失败，请检查新库表结构和账号查询权限。";
        return result;
    }

    while (query.next()) {
        EventData event;
        // 列号从0开始，与上面SELECT字段顺序一致。
        event.id = query.value(0).toString();
        event.cameraName = query.value(1).toString();
        // 这里按项目约定把存储时间当作UTC显示，不进行本地时区转换。
        event.occurredAt = query.value(2).toDateTime().toString("yyyy-MM-dd HH:mm:ss.zzz");
        event.type = query.value(3).toString();
        event.description = query.value(4).toString();
        event.status = query.value(5).toString();
        result.events.append(event);
    }
    if (query.lastError().isValid()) {
        result.events.clear();
        result.error = "读取事件结果失败，请重试。";
    }
    return result;
}
```

```cpp
void ReviewWidget::refresh() { loadPage(); }
void ReviewWidget::resetQuery(bool enabled)
{
    // 点“全部记录”时关闭日期筛选；点日期查询时，只看选中的那一天。
    byDate=enabled; selectedDate=datePicker->getDate(); page=1; loadPage();

void ReviewWidget::loadPage()
{
    if (typeBox->currentIndex() == 1) {
        loadEvents();
        return;
    }
    // View 只把查询条件交给 Service，再把返回的这一页显示出来。
    auto result=service.query(typeBox->currentIndex()==1,byDate,selectedDate,page,pageSize->currentText().toInt());
    // 先清掉旧数据，查询失败时就不会还显示上一次的结果。
    table->clear();
    table->setRowCount(0);
    detail->setText("双击记录可打开本机视频文件。");
    // 下面会用代码调整页码，先暂停信号，免得又触发一次 loadPage。
    jump->blockSignals(true);
    if (!result.error.isEmpty()) {
        count->setText("加载失败");
        detail->setText(result.error);
        page=pages=1;
        jump->setRange(1,1); jump->setValue(1); jump->setEnabled(false);
        previous->setEnabled(false); next->setEnabled(false);
        jump->blockSignals(false);
        return;
    }
    table->setColumnCount(result.headers.size());
    table->setHorizontalHeaderLabels(result.headers);
    table->setRowCount(result.rows.size());
    for(int r=0;r<result.rows.size();++r)
        for(int c=0;c<result.rows[r].size();++c)
            table->setItem(r,c,new QTableWidgetItem(result.rows[r][c]));
    table->horizontalHeader()->setSectionResizeMode(QHeaderView::ResizeToContents);
    table->horizontalHeader()->setStretchLastSection(true);
    page=result.page; pages=result.pages;
    jump->setRange(1,pages); jump->setValue(page); jump->setEnabled(result.total>0);
    jump->blockSignals(false);
    // 第一页不能再往前，最后一页不能再往后。
    previous->setEnabled(page>1); next->setEnabled(page<pages);
    count->setText(QString("共 %1 条 · 第 %2 / %3 页").arg(result.total).arg(page).arg(pages));
    if(result.total==0) detail->setText("当前条件下没有记录，可以更换日期或查看全部记录。");
}

void ReviewWidget::loadEvents()
{
    // 界面只调用业务层，不写SQL；先清除旧内容，失败时不会残留上次结果。
    table->clear();
    table->setRowCount(0);
    table->setColumnCount(6);
    QStringList headers;
    headers << "编号" << "摄像头" << "时间（UTC）" << "事件类型" << "事件描述" << "状态";
    table->setHorizontalHeaderLabels(headers);
    previous->setEnabled(false);
    next->setEnabled(false);
    jump->blockSignals(true);
    jump->setRange(1, 1);
    jump->setValue(1);
    jump->setEnabled(false);
    jump->blockSignals(false);

    EventResult result = eventService.queryLatest(eventConfigPath);
    if (result.error.isEmpty() == false) {
        count->setText("新库事件加载失败");
        detail->setText(result.error);
        return;
    }

    for (int row = 0; row < result.events.size(); row++) {
        EventData event = result.events.at(row);
        table->insertRow(row);
        table->setItem(row, 0, new QTableWidgetItem(event.id));
        table->setItem(row, 1, new QTableWidgetItem(event.cameraName));
        table->setItem(row, 2, new QTableWidgetItem(event.occurredAt));
        table->setItem(row, 3, new QTableWidgetItem(event.type));
        table->setItem(row, 4, new QTableWidgetItem(event.description));
        table->setItem(row, 5, new QTableWidgetItem(event.status));
    }
    table->horizontalHeader()->setSectionResizeMode(QHeaderView::ResizeToContents);
    table->horizontalHeader()->setStretchLastSection(true);
    count->setText(QString("新库事件：已显示 %1 条（最多100条）").arg(result.events.size()));
    detail->setText("当前展示新库最近100条事件；日期和分页将在阶段3接入。合成事件仅供测试，暂不支持录像播放。");
    if (result.events.isEmpty()) {
        detail->setText("新库暂无事件。连接和查询已成功，目前没有可显示的数据。");
    }
}
```
