# 阶段16 真实YOLO检测与事件闭环学习手册

## 已实现和输入来源
检测进程实际运行Ultralytics YOLOv5n v7 ONNX模型，CPU推理。模型版本yolov5n-v7-04f0e55c26f58d17。
测试使用上游公开的双人图片生成本机视频，再实际推流、录制、检测。它证明模型推理链路，不代表已接入真实安防摄像头。
规则是“检测框中心位于配置区域内的person”，不是轨迹越界、身份识别或完整行为理解。
本机合成test模式已经关闭，正式入口只使用onnx。

## 文件和调用链
inference.py负责FFmpeg采样、OpenCV解码/letterbox/RGB转换、ONNX输入、NMS与ROI过滤；worker.py接入真实Engine并将模型版本加入缓存指纹。
backend/detectionjobs.cpp验证RPC响应，事务写入事件与成功任务；apiserver返回录像关联；EventData/RecordPage增加隐藏证据id；ReviewWidget加入检测按钮、任务轮询和事件双击回放。
MainWidget增加退出登录，并保留窗口缩放；本机启动器管理服务与演示推流。
完整链路：登录 → 选设备录一段 → ready录像 → 点击检测 → C++任务 → gRPC → FFmpeg取0.3秒帧 → OpenCV → ONNX → ROI规则 → 事件入库 → 事件列表 → 双击证据回放。

## 前处理逐步解释
模型输入1×3×640×640，输出1×25200×85。先按比例缩到640范围，再补114灰边，BGR转RGB，HWC变CHW，除255归一化。
实际下载模型输入为float16；第一次按float32运行报类型错误，现按session输入类型转换，不能凭经验固定输入类型。
后处理用objectness乘person类别概率，阈值默认0.25，NMS IoU阈值0.45；扣除letterbox偏移并映射回原图，输出归一化坐标。
ROI用0到1坐标，检测框中心在区域内才通过。不是框与区域相交就自动通过。

## 事件和去重
RPC响应必须synthetic=false且模型版本匹配，检测数量、置信度和坐标均校验。
事件键为person:cameraId:recordingId，同一录像同一人员规则跨任务最多一条。数据库唯一键兜底，任务重试和另起任务都不重复生成事件。
这不是跨不同录像的时间冷却去重；多区域独立规则ID、轨迹跟踪和跨片段去重尚未实现。
事件与任务成功状态在同一个MySQL事务提交，避免成功任务没有事件。文件系统仍不属于数据库事务，录像对账边界见阶段13。
事件时间按录像开始加采样0.3秒估算，不声称与摄像头绝对时间逐帧对齐。

## 原窗口集成
管理员在录像列表选ready行点击检测，后台提交任务并定时查状态；界面显示人员数与事件id。
事件表第一列隐藏元数据保存recordingId，双击通过权限接口下载，不拼接用户磁盘路径。
GUI测试发现SQL NULL录像id被驱动转成字符串0，已在服务端与客户端两层处理为空/无关联，合成事件不再误下载id=0。
长描述列改为自适应换行，状态列保持可见，计数和提示在深色背景显示浅色。

## 实际结果
公开静态图原图：2个人，实际推理返回2个person，置信度约0.790、0.369；彩色测试片采样返回0。
完整流录制后：录像id3、事件id28，真实检测2人，置信度约0.812、0.482。
同一jobKey重试复用任务；同一录像换新jobKey命中同一事件；角落ROI返回0；无人员录像返回0；viewer可查看被授权事件及关联录像。
这仅是少量功能样本：一个含人正样本和一个无人员负样本，事件级观察误报0/1、漏报0/1，不足以估计真实场景准确率，没有做IoU标注集评估或mAP测试。
real_detection_check通过完整接口链路。detection_ui_check验证原窗口事件关联回放和检测结果提示；窗口1000×700仍可缩放。

## 可靠性边界
每段只采一个0.3秒帧，不是持续实时检测，短暂出现的人可能漏掉；后续应采样多帧和评估成本。
模型在CPU运行，单次底层session.run不支持本代码立即强制中断；deadline后检查取消，结果不提交副作用。
启动器运行独立服务，凭据只在本地配置，模型与Python依赖属于运行资源，不能作为一次性文件删除。

## 面试追问与答案
1. 容器和编码和模型分别是什么？MP4容器装编码视频，FFmpeg解码出图像，模型对图像做检测，三者不是同一层。
2. 为什么letterbox而非直接拉伸？保持宽高比，后处理必须反向扣除补边并除缩放比例。
3. 为什么乘objectness？本YOLOv5输出目标存在概率与类别概率分开，最终person置信度需要结合；不能直接套所有YOLO版本。
4. NMS做什么？同一对象多个重叠候选框按分数去重，IoU是框重叠度，不是模型识别人准确率。
5. 阈值越高越好吗？会减少部分误报，也可能增加漏报，必须按标注场景评估。
6. ROI怎么变成事件？模型框先过类别/阈值/NMS，再过中心点区域规则，最后形成业务事件；模型输出不直接等于告警。
7. 怎样避免重复事件？任务键和请求指纹处理调用幂等，数据库事件键按录像规则去重，事务统一提交。
8. 模型换了为什么要改版本？缓存与业务结果必须能追溯对应权重；本例用文件SHA前16位作为版本部分。
9. 2张样本都正确能说准确率100%吗？不能，样本极少且缺少代表性，本次只报告功能样本观察结果。
10. 模型超时会怎样？客户端有deadline，worker协作检查，C++写失败状态；不把超时当成功空检测。
11. 当前实时检测完成了吗？没有，完成的是独立检测服务与录像单帧检测闭环，持续多帧采样和真实摄像头压力验证仍待做。
