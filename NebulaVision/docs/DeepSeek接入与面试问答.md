# DeepSeek接入与面试问答

## 使用方法与状态
在原主窗口顶部打开查询助手，点击DeepSeek设置，在密码输入框粘贴DeepSeek开放平台API Key并保存。然后勾选使用DeepSeek解读，再输入设备列表、日期事件或文档问题并查询。没有勾选时保留本机查询和检索方式。

API Key是开放平台给程序使用的密钥，不是DeepSeek网页登录密码，也不是本项目登录密码。不要把密钥发到聊天或写进Git。本次机器尚未配置真实Key，因此完成了协议替身测试和Qt编译，尚未获得真实DeepSeek返回，不称为真实模型联调通过。

当前默认模型deepseek-flash及请求格式根据2026年11月3日官方文档核对；接口固定为https://api.deepseek.com/chat/completions。模型可通过本机配置或环境变量切换为deepseek-v4-pro。没有使用过时的deepseek-chat默认名。

## 改动与调用链
agent/deepseek.py新增配置读取、官方HTTPS请求、超时、响应检查与脱敏错误处理。agent/deepseek.example.json只提供空密钥样例。agent/client.py在现有查询或检索完成后调用生成器。view/mainwidget.cpp新增设置按钮、勾选项及65秒整个助手进程时限。tests/deepseek_check.py覆盖协议和失败分支。

调用顺序：当前账号通过业务API验证 → LangGraph业务查询或Qdrant文档检索 → 得到原始证据 → 若启用DeepSeek则读取本机Key → HTTPS发送问题和证据 → 检查回答是否完整 → 在原界面展示生成解读及原始证据。

模型只解释现有证据，没有获得SQL、shell、录像或任何业务写入工具。当前问题解析仍使用已有规则，不是让模型自主选择工具。模型生成发生在已完成查询之后，不放入LangGraph的持久化状态；重试会重新请求模型，可能产生额外用量。

## 代码逐段讲解
load_settings先看进程环境变量DEEPSEEK_API_KEY，再读取外部资源目录deepseek.local.json。环境变量优先，改文件不会覆盖已有环境变量。模型同样支持DEEPSEEK_MODEL。缺少Key时抛出ModelError，给用户明确的设置提示。

本机文件保存位置默认C:\Users\23974\Desktop\jk\x\deepseek.local.json，也可由现有资源目录配置改变。它是本地明文配置，不是加密保险库；Qt尝试设置为所有者读写，但Windows实际访问范围仍取决于系统ACL。不要分享整个x目录。*.local.json已被Git忽略，密钥不会写入源码、命令行参数或checkpoint。

generate将问题和证据写进messages。system说明模型只能依证据解释，user用JSON把问题和证据作为数据传入。登录token、MySQL密码和整个本机配置不会放进提示词。勾选项明确告知这些问题及证据将发往DeepSeek，可能产生平台API费用。

urllib.request.Request构造POST请求。Authorization的Bearer后面放API Key，它属于HTTP认证头，不属于提示词。Content-Type说明正文是JSON。请求正文按UTF-8编码，与Qt进程间输入的UTF-8保持一致。

stream=false表示一次取得完整JSON，而不是逐字流式显示。max_tokens=1200限制本次回答长度；thinking设为disabled，使用非思考模式减少等待。网络超时40秒，Qt对整个子进程设置65秒截止时间。不自动重试，避免一次点击反复产生API用量。

响应只接受finish_reason为stop的非空文字。长度截断、格式错误、网络失败、401密钥错误、402余额不足和429限流会给出不同的脱敏说明。原始平台错误正文可能含敏感信息，所以不直接展示；生成失败仍显示已查到的原始证据，不伪装成成功回答。

NoRedirect禁止请求跳转，以免认证头被转发到意外地址。接口地址固定，不允许问题文本改目的地址。文档没有可核对证据时不调用模型，不让它凭空补答案。

## 输出可信度
模型收到的是提示约束，不是事实证明。当前没有实现每句话的自动事实校验，仍可能误读证据。因此生成文字明确标为DeepSeek生成解读，并附原始计数、API来源或文档引用供核对。模型输出不会作为下一次工具执行指令。

## 验证情况
4组自动测试通过：请求地址及认证头、提示词不含测试密钥、保留原始证据；缺Key提示；401/402/429/500及跳转错误不泄露原文且不自动重试；超时、无效JSON、缺字段和回答截断拒绝。测试全部使用替身，没有调用收费接口。

真实平台联调待用户在设置窗口填写API Key后执行。尚未验证真实账户余额、平台延迟、实际回答质量和引用准确率。不得把替身返回描述为DeepSeek真实生成。

## 面试追问及答案
问题1：API Key和业务token区别是什么？答：业务token决定能查询本项目哪些资源；DeepSeek Key用于认证模型平台及计费用量，不能相互代替。追问：模型能拿业务token查库吗？答：不能，本次没有把token传给模型。

问题2：为什么模型前面先查业务API？答：权限过滤和事实查询由已有后端完成，模型只解释已有证据。追问：提示词说不能越权就够了吗？答：不够，权限必须在工具与后端实际执行。

问题3：为什么保留原始证据？答：方便核对数量、时间与引用，区分模型解读和业务事实。追问：有引用就没有幻觉吗？答：仍可能引用不当或误读，当前没有逐句验证。

问题4：为什么不自动重试？答：网络超时不代表平台没执行，再请求可能重复计费。追问：用户再次点击呢？答：会再次调用，界面和文档明确说明；未实现平台级幂等生成缓存。

问题5：设置存在本机文件是不是安全加密？答：不是，只是避免进入源码和Git，文件仍需系统权限保护。追问：正式部署怎么做？答：应迁到服务端秘密管理或系统凭据存储，并控制调用账号及用量。
