# 阶段13 录像索引和回放闭环

## 已实现的范围
管理员可在设备列表选择摄像头录制6秒，也可调用capture接口录制2至30秒的一段。最多两段同时录制；不是24小时连续录像调度。
202返回writing索引，后台录制到.part.mp4，验证能解码后重命名为正式mp4，再更新ready和字节数。失败标failed，服务重启将遗留writing标interrupted。
原回看页的录像和事件都改走API，不再调用旧录像SQL。双击ready录像，经鉴权下载到x/playback-cache，在原监控页用FFmpeg回放。

## 文件改动
backend/serverdb.h提取请求连接管理；recorder.h/.cpp做后台封片；apiserver增加capture、列表和文件接口；main启动恢复旧writing。
service/recordservice.h改为API；reviewquerytask统一事件/录像后台分页结果；reviewwidget重用原日期和分页并加入下载回放信号；mainwidget接收信号切到监控页；monitorwidget增加录制按钮。
ApiClient::download用QSaveFile写临时缓存，成功才commit，下载失败不留下伪完整文件。

## 调用链
录制按钮 → capture接口鉴权管理员/摄像头 → 插入writing → QtConcurrent录制 → 解码验证 → 原子同目录重命名 → 更新ready。
回看页 → recordings API分页 → 选择ready行 → file API再次校验camera权限 → 下载缓存 → recordingReady信号 → 监控页通道0播放。
服务端只接受数字录像id，使用数据库object_key映射文件，不接受客户端任意磁盘路径。
文件不存在返回410，未ready返回409，匿名401。开发文件下载上限64MiB，响应当前整文件读取，不是带Range的大规模流媒体下载。

## 关键问题与修正
第一次3秒流拷贝在长GOP流中生成292字节空片，解码验证失败，正确标failed。
调整为setpts重置时间轴并用libx264编码后完成短片。本实现选择可独立解码的短片而非零转码开销，CPU成本增加。
开始/结束索引记录墙钟时间，不声称与媒体PTS逐帧精确对齐。实际文件与数据库更新不是一个原子事务，DB失败时保留文件待对账；自动孤儿扫描/补偿尚未实现。
低于32MiB可用磁盘空间拒绝录制；真实磁盘满故障尚未注入测试。

## 实测
recording_check通过：实际授权RTSP录制、ready索引、viewer授权下载、下载视频解码、匿名拒绝、非法id拒绝、文件临时移开返回410且立即恢复。
recording_ui_check退出码0：原窗口API登录、原回看页录像列表、双击下载、切回原监控页实际产生视频帧。
保留了本轮可回放的合成流录像；失败片段也保留失败状态，没有伪装成真实摄像头录像。

## 入门逐段讲解
### 为什么capture先返回202
录6秒不应该让按钮在UI里卡6秒。服务端先写一条writing记录并返回任务id，后台完成后更新ready或failed，回看页稍后刷新。
### 临时文件和正式文件
先写随机文件名的.part.mp4，等FFmpeg正常结束且能解码，再重命名为正式文件。数据库只把ready当可回放。
QFile::rename在同一目录发布已经完成的文件；它不能替代数据库事务。重命名后数据库更新失败时，文件可能存在但没有ready索引，这就是后续需要对账的原因。
### 视频为什么存在磁盘
录像表保存文件键、大小、摄像头、时间和状态，不把整个视频塞进每一行。客户端只发送录像id，服务器查到文件键后组合受控根目录，不接受任意文件路径。
### 回放为何先下载
```text
录像id → 鉴权下载接口 → QSaveFile临时缓存
       → 下载成功commit → recordingReady信号
       → 主窗口切监控页 → FFmpeg播放缓存
```
这套开发方案没有实现大文件Range边下边播，64MiB限制也是明确边界。QSaveFile失败时cancelWriting，避免残片误当成功缓存。
追问：writing和failed为什么不能双击播放？答案：前者未确认封片，后者已经失败，界面不能因为文件名存在就假定有效。

## 面试追问与答案
1. 写文件和写数据库能放一个事务吗？普通MySQL事务不能覆盖文件系统，需要状态机、临时文件及对账补偿。
2. 为什么.part文件不直接播放？它可能未封片或中途失败，只有验证完成才发布ready。
3. 为什么短片不直接copy？受关键帧间隔影响，测试中出现空片；本轮改为重新编码，代价是CPU。
4. 录像权限在哪里校验？列表与下载都按camera_id校验，不能只给列表过滤。
5. 为什么下载用QSaveFile？下载失败可取消临时写入，避免残缺文件被当成完整录像。
6. 关闭窗口下载还在后台怎么办？任务不捕获窗口指针，QObject上下文断开回调；缓存任务可能继续到超时，但不会更新已销毁控件。
7. 这算完整录像系统吗？完成了短片录制到回放闭环，连续调度、磁盘配额、Range下载和自动对账未完成。

## 练习
管理员登录，选演示设备录6秒，等待后进入回放选择录像，观察writing到ready，再双击播放。没有正在推流时应看到失败，而不是空白录像被当成功。
