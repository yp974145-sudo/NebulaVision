## 日期怎么筛选
```sql
WHERE e.occurred_at >= :begin AND e.occurred_at < :end
```
begin是当天00:00:00，end是次日00:00:00。包含左边、不包含右边，叫半开区间。
这样当天23:59:59.999不会遗漏，次日零点也不会混入。
prepare准备SQL，bindValue给占位符赋值，exec执行。日期不会直接拼接进SQL。
Lambda bindDate只负责为统计与列表两个查询绑定相同起止时间，避免两份条件不一致。

## 分页怎么算
```cpp
pages = qMax(1, (total + size - 1) / size);
page = qBound(1, requestedPage, pages);
offset = (page - 1) * size;
```
25条每页10条得到3页；第3页OFFSET为20，剩5条。
空结果仍用第1页表示，避免显示第0页；跳到99页时收敛到实际末页。
SQL用LIMIT :size OFFSET :offset控制结果数量。页码变化时数据库只返回当前页。

## 面试追问和答案
1. 为何不查到23:59:59？会漏掉带毫秒的记录，使用次日零点之前更准确。
追问 日期按哪个时区？当前按UTC日期，界面标明UTC；将来若按用户本地日期，需转换起止边界。
2. 为何先COUNT？计算总页数和修正越界页码，COUNT与列表条件必须一致。
追问 两次查询中新增数据怎么办？可能不一致，严格要求时应考虑事务快照或其他分页契约。
3. OFFSET缺点是什么？深分页需跳过大量记录，可能慢；后续大数据量考虑基于时间和id的游标分页。
4. 为何排序带id？时间重复时仍有确定次序，但动态数据插入引起的跨页变化仍需另处理。
5. prepare/bindValue有什么用？将参数与SQL结构分开，减少注入和转义错误。
6. qBound是什么？把数值夹在上下限之间，例如qBound(1,99,3)得到3。
