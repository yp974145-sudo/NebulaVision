# 阶段4 异步事件查询学习手册

## 已实现的行为
新事件查询移出GUI线程。界面仍可点击、计时和关闭。连续刷新时同时最多一个查询，旧查询结束后只执行最新条件，不无限排队。
本阶段只改新事件分支，旧录像分支仍同步，后续迁移时另处理。

## 修改清单
service/eventquerytask.h/.cpp新增QThread任务；reviewwidget.h/.cpp负责启动任务、接收结果、过滤旧结果和销毁任务；eventservice.h支持可选NEBULAVISION_DEV_CONFIG配置路径；devdbconnection.cpp增加MySQL读写超时；pro加入新线程文件。
环境变量只指定配置文件位置，不包含密码。默认仍从项目本地viewer.local.json读取。

## 为什么原来会卡
原来loadEvents直接调用Service，SQL没有结束，GUI线程就无法继续处理绘制和点击。
现在run()在工作线程执行，GUI线程只负责显示，完成后用信号把结果送回GUI线程。
```text
GUI loadEvents → 创建EventQueryTask并start
工作线程run → 创建Service → 创建新连接 → 查询 → 释放连接 → 发出resultReady
GUI showEvents → 检查请求号 → 更新表格
```
QThread对象本身创建在GUI线程，但重写的run在新线程执行；不能因此把所有QThread成员函数都说成运行在工作线程。

## EventQueryTask逐步理解
构造函数复制配置路径、日期、页码、条数和请求号，保存一份参数快照。
run内部创建EventService，它再创建数据库连接；连接的创建、查询和销毁全部发生在同一个工作线程。
emit resultReady(requestId,result)发出结果，没有直接操作任何控件。
Q_DECLARE_METATYPE和qRegisterMetaType让自定义EventResult可以通过队列连接传递，Qt需要复制这份值。

## 界面怎样管理任务
loadEvents每次增加eventRequestId，代表用户最新请求。忙时只更新条件，不创建另一个任务。
startEventQuery把当前条件复制给任务，resultReady使用Qt::QueuedConnection连接showEvents。
showEvents比较结果请求号：不是最新的就直接丢弃；已经切到旧录像页也不显示。
finished后释放任务，如果用户条件已变化，则启动最新请求。旧请求不会无限积压。
切到旧录像页也递增请求号，使尚未完成的新事件结果过期。

## 窗口关闭如何处理
析构函数断开任务回调，wait等待run结束，再删除任务。没有使用terminate强杀。
驱动设置连接超时3秒、读写超时5秒，减少数据库卡住的风险；超时不是数学意义的整体执行上限，关闭时仍可能短暂等待，未声称随时毫秒退出。
没有实现驱动级立即取消正在执行的SQL。request号过滤属于逻辑取消，不会让服务器上的SQL立刻停下。

## 实际验证
Qt5.9.8/MinGW5.3主程序编译通过。stage4_check退出码0。
用独立MySQL连接对新库events表短暂加写锁约2秒，模拟实际慢查询。查询等待时20毫秒GUI计时器持续触发，解除锁后正常显示事件。测试连接退出后锁释放，没有改表数据。

## 面试追问和答案
1. 信号槽自动异步吗？不是。本次显式使用工作线程和QueuedConnection。
追问 信号的槽在哪个线程？这里接收窗口属于GUI线程，队列槽由GUI事件循环执行。
2. 为什么连接不能从GUI直接传给任务？数据库连接有线程归属，应在使用线程创建和清理。复制QSqlDatabase不会产生独立连接。
3. 请求号解决什么？旧结果晚返回不能覆盖新条件。它是结果有效性判断，不是数据库物理取消。
4. 如何避免每次点击都开线程？同时最多一个任务，记录最新条件，结束后只补最新一次。
5. 为什么QThread对象在GUI却run在后台？QThread是管理线程的对象，start创建线程执行run，对象本身的QObject归属不自动迁移。
6. 为什么不能工作线程setItem？控件应在GUI线程操作；后台只生成普通数据。
7. 窗口关闭结果才返回怎么办？断开回调并等待任务结束，释放对象，避免悬空访问和运行中销毁QThread。
8. 有没有真正实现立即取消？没有。当前靠逻辑取消和驱动超时，严格立即取消需额外设计。
