# 阶段8 四画面与有界帧缓存学习手册

## 本阶段成果
原监控页保留左侧通道选择、单/四画面概念，使用同一组四个播放器切换布局。每个通道独立打开本地文件或RTSP，可暂停、继续、停止当前通道、全部停止。

## 代码改动

view/monitorwidget.h/.cpp：把原单路与四路占位布局整理成四个独立tile和同一组播放器，增加当前通道操作及stopAll；切布局不创建新解码器。
tests/stage8_check.cpp/.pro：四路实际解码、丢帧、布局、停止和关闭验证。
原阶段2测试同步为等待异步查询；阶段5探针测试结束时显式解除来源。阶段4测试工程末尾空行清理。

## 最新帧缓存为什么只有1帧
监控预览关心当前画面。GUI忙时继续排队每一帧会让内存和延迟增加，恢复后还在播放旧画面。
本实现把尚未显示的一帧保存在latestFrame，下一帧到来时覆盖它并增加dropped。
```text
解码线程产生新帧 → 加锁 → 覆盖旧的待显示帧 → 解锁
GUI每33毫秒检查 → 加锁 → 取走最新帧并清空标志 → 解锁 → 显示
```
这是容量1的有界邮箱，不是保存所有视频帧的录像队列。录像不能直接照搬丢旧帧策略。

## 关键代码怎样理解
```cpp
QMutexLocker lock(&frameMutex);
if (hasFrame) ++dropped;
latestFrame = frame.copy();
hasFrame = true;
```
QMutexLocker构造时加锁，离开大括号自动解锁，防止生产线程和GUI同时改共享图像。
frame.copy独立拥有像素内存；latestFrame被替换后旧图像在无其他引用时释放。
GUI的takeFrame将图像值交出去，清空缓存并将hasFrame置false。QImage使用隐式共享，不意味着跨线程同时修改同一份像素是安全的。

## 内存边界如何描述才准确
每帧640×360×3=691200字节，约0.659MiB。四路待显示缓存最多4帧，约2.637MiB。
每路组装中的buffer也最多一帧，另外还有当前显示图像、QPixmap、Qt/进程管道缓存和FFmpeg内部数据。
所以“缓存容量1帧”不等于整个播放器只占一帧内存。总内存以进程测量为准，不能只拿图像字节数当总量。
GUI用定时器拉取，没有每一帧都排入GUI事件队列。状态和错误仍是低频控制信号。

## 四画面怎样复用
每个通道有一个FfmpegPlayer、一个显示控件、一个状态标签。
updateLayout先把tile从网格取下，再按单画面或2×2重新加入。同一批对象复用，视频播放不会因为切布局重新启动。
左侧currentRowChanged更新selectedChannel；打开、暂停、继续、停止针对该索引。stopAll依次停止四路。
MonitorWidget析构先stopAll，确保工作线程和子进程退出，再由父子对象关系销毁控件。
隐藏通道仍继续播放，这一策略用于保留布局切换时的播放状态，不能宣称隐藏就不耗CPU。

## 实测结果
Qt5.9.8/MinGW5.3 32位主程序和stage8_check编译通过，四路使用本地25秒合成H264视频、输出640×360/15fps静音预览。
第一次完整测试退出码0，四路显示帧分别86、98、97、97。故意让GUI停顿1秒后，覆盖待显示旧帧共71帧，各路缓存仍不超过1。
切单/四布局正常；停止第1路后其帧数不再增加而其他路继续；全部停止后不再显示帧；重新打开四路后立即销毁窗口，正常回收。
四画面截图已检查，左侧标题和通道列表截断问题已增大侧栏并允许标题换行。
短时资源采样覆盖客户端进程树6个进程（含系统辅助进程），约4.03秒：单逻辑核心等效CPU约19.0%，32逻辑处理器整机归一化约0.59%；私有内存总和约314.7MiB至314.5MiB。
这是短时本机样片测试，不代表真实4路摄像头、高分辨率、长时间或不同编码性能，也不是内存泄漏长期证明。
原始计数与资源JSON、截图位于x/验证记录。最终回归结果另见阶段汇总。

## 面试追问与答案
1. 为什么队列有上限？限制内存和延迟，生产快于消费时必须有背压或丢弃策略，不能无限存。
追问 为什么丢旧帧？预览优先新鲜度，旧帧价值较低；录像业务应另设计，不能随意丢失证据。
2. 容量1帧是不是没有队列？它是容量为1的有界缓存/邮箱，仍有明确生产者、消费者和覆盖规则。
3. 互斥锁保护什么？latestFrame、hasFrame和dropped的共同状态；不在锁里操作窗口。
追问 为什么不用原子bool替代锁？原子标志不能单独保护图像对象和计数等复合操作的一致性。
4. 为什么不每帧emit给GUI？排队信号可能积压图像；定时拉取最新帧使数据量有上限。
5. QImage和QPixmap有什么区别？本实现在线程里准备QImage像素，在GUI线程创建和显示QPixmap。
6. 四个播放器能共用一个停止标志吗？不应这样做，否则停止一个通道可能影响其他通道；每个任务独立状态。
7. 切换布局为什么不重新new？复用对象避免重复解码和资源泄漏，并保留播放位置。
8. 关闭时为什么先停止再删除？父子关系只解决对象销毁归属，不能替代线程/进程退出协议。
9. 性能怎么测？除客户端外还计入解码子进程，记录输入、输出分辨率、帧率、时间窗口和处理器数量，避免只报单个好看的数字。
10. 已经验证没泄漏吗？短时测试内存稳定、退出回收通过；长期压力和真实流仍未完成，不能下绝对结论。
